\section{Ce que vous allez installer}
% =====================================================================

Tout l'environnement tourne dans \textbf{Docker} : vous n'installez ni Java, ni Spark, ni Python à la main.
Une seule commande démarre l'ensemble des services suivants.

\begin{center}
\begin{tikzpicture}[
  font=\sffamily\small, >=Stealth,
  svc/.style={draw=#1,fill=#1!8,rounded corners=3pt,thick,minimum width=3.3cm,minimum height=1.1cm,align=center},
  opt/.style={svc=#1,dashed}]
\node[svc=lhblue] (jup) {\textbf{JupyterLab + Spark}\\\scriptsize vous codez ici};
\node[opt=lhteal, right=0.8cm of jup] (trino) {\textbf{Trino}\\\scriptsize requêtes SQL};
\node[opt=orange, right=0.8cm of trino] (sup) {\textbf{Superset}\\\scriptsize tableaux de bord};
\node[svc=lhviolet, below=1cm of trino] (cat) {\textbf{Catalogue Iceberg}\\\scriptsize liste des tables};
\node[svc=gray, left=0.8cm of cat] (pg) {\textbf{PostgreSQL}\\\scriptsize base source};
\node[svc=lhbronze, below=1cm of cat, minimum width=11.5cm] (s3)
  {\textbf{Stockage S3 (RustFS)} -- les fichiers de données\\
   \scriptsize \texttt{landing/} \quad $\rightarrow$ \quad
   \colorbox{lhbronze!30}{bronze} \quad $\rightarrow$ \quad
   \colorbox{lhsilver!30}{silver} \quad $\rightarrow$ \quad
   \colorbox{lhgold!30}{gold}};
\draw[->] (jup) -- (cat);
\draw[->] (trino) -- (cat);
\draw[->] (sup) -- (trino);
\draw[->] (cat) -- (s3);
\draw[->] (jup.south west) ++(0.4,0) |- ([yshift=0.3cm]s3.north west) -- ([xshift=0.4cm]s3.north west);
\draw[->,dashed] (pg) -- (jup);
\end{tikzpicture}

{\footnotesize Pointillés : services facultatifs, à lancer seulement avec 12 Go de RAM ou plus.}
\end{center}

\textbf{L'idée à retenir.} Les données sont stockées \emph{une seule fois} dans le stockage S3.
Le catalogue sait où se trouve chaque table. Plusieurs outils (Spark, Trino, Superset) lisent
\emph{les mêmes tables} sans les copier : c'est le principe du Lakehouse.

\section{Installer Docker}
% =====================================================================

\begin{tabularx}{\textwidth}{@{}>{\bfseries}p{2.2cm}X@{}}
\toprule
Windows & 1. Ouvrir PowerShell \emph{en administrateur} et taper \cmd{wsl -{}-install}, puis redémarrer.\newline
          2. Installer \textbf{Docker Desktop} (\url{https://docs.docker.com/desktop/}) en gardant l'option \og WSL 2 \fg{}. \\
\midrule
macOS   & Installer \textbf{Docker Desktop} en choisissant la version de votre processeur (Apple Silicon ou Intel). \\
\midrule
Linux   & \cmd{curl -fsSL https://get.docker.com | sh} \newline
          puis \cmd{sudo usermod -aG docker \$USER} et se reconnecter. \\
\bottomrule
\end{tabularx}

\textbf{Mémoire.} Dans Docker Desktop, menu \emph{Settings > Resources}, donnez à Docker
\textbf{6 Go} (machine de 8 Go) ou \textbf{10 Go} (machine de 16 Go).

\textbf{Vérification} dans un terminal :
\begin{lstlisting}[style=shell]
docker compose version
docker run --rm hello-world
\end{lstlisting}

\begin{resultat}
Une version \texttt{v2.x} s'affiche, puis le message \texttt{Hello from Docker!}
\end{resultat}

\section{Installer l'environnement du cours}
% =====================================================================

Toutes les commandes s'exécutent dans un terminal (sous Windows : le terminal \textbf{Ubuntu} installé avec WSL).

\subsection*{Étape 1 -- Récupérer le dossier du cours}
\begin{lstlisting}[style=shell]
git clone https://github.com/moeJEE/lakehouse-tp.git
cd lakehouse-tp
\end{lstlisting}
Sans Git : téléchargez le fichier ZIP depuis la page du dépôt et décompressez-le.

\subsection*{Étape 2 -- Créer le fichier de configuration}
\begin{lstlisting}[style=shell]
cp .env.example .env
\end{lstlisting}
\textbf{Machine de 8 Go uniquement :} ouvrez \cmd{.env} et remplacez \cmd{JUPYTER\_MEM\_LIMIT=4g} par \cmd{3g}.

\subsection*{Étape 3 -- Télécharger les images (le plus long)}
\begin{lstlisting}[style=shell]
docker compose --profile full pull
\end{lstlisting}
Si le téléchargement s'interrompt, relancez simplement la même commande.

\subsection*{Étape 4 -- Démarrer}
\begin{lstlisting}[style=shell]
docker compose up -d
\end{lstlisting}

\subsection*{Étape 5 -- Contrôler l'état des services}
\begin{lstlisting}[style=shell]
docker compose ps
\end{lstlisting}

\begin{resultat}
Après environ une minute, \texttt{rustfs}, \texttt{iceberg-rest}, \texttt{postgres} et \texttt{jupyter}
sont à l'état \texttt{running}. Le service \texttt{init-buckets} est à l'état \texttt{exited (0)} :
c'est normal, il a préparé le stockage puis s'est arrêté.
\end{resultat}

\subsection*{Étape 6 -- Lancer le test automatique}
\begin{lstlisting}[style=shell]
docker compose exec jupyter python /opt/lakehouse/scripts/check_env.py
\end{lstlisting}

\begin{resultat}
\begin{lstlisting}[basicstyle=\ttfamily\footnotesize,backgroundcolor=\color{white},frame=none]
[OK] 1. Stockage S3 (RustFS)
[OK] 2. Catalogue Iceberg REST
[OK] 3. PostgreSQL
[OK] 4. Spark + Iceberg
[OK] 5. Spark + Delta Lake
[OK] 6. DuckDB lit les fichiers sur S3
[--] 7. Trino (profil sql/full non démarré ?)
ENVIRONNEMENT PRÊT
\end{lstlisting}
\textbf{Faites une capture d'écran de ce résultat : c'est votre livrable.}
La ligne 7 en \texttt{[--]} est normale : Trino et Superset \textbf{ne démarrent pas automatiquement}
(ils demandent 2,5 Go de RAM en plus). Avec 16 Go de RAM, lancez-les puis refaites le test :
\begin{lstlisting}[style=shell]
docker compose --profile full up -d
\end{lstlisting}
La ligne 7 passe alors en \texttt{[OK]}. Il suffit de le faire une fois : ils redémarreront ensuite
seuls avec Docker.
\end{resultat}

\section{Premier test dans JupyterLab}
% =====================================================================

Dans JupyterLab, créez un notebook dans le dossier \texttt{notebooks/} et exécutez ces trois cellules.

\textbf{Cellule 1 -- Démarrer Spark}
\begin{lstlisting}[language=Python]
from pyspark.sql import SparkSession
spark = SparkSession.builder.appName("premier_test").getOrCreate()
\end{lstlisting}

\needspace{10\baselineskip}
\textbf{Cellule 2 -- Créer une table, puis la modifier}
\begin{lstlisting}[language=Python]
spark.sql("CREATE NAMESPACE IF NOT EXISTS lakehouse.bronze")

spark.sql("""
    CREATE OR REPLACE TABLE lakehouse.bronze.villes
    (nom STRING, population BIGINT) USING iceberg
""")

spark.sql("""
    INSERT INTO lakehouse.bronze.villes
    VALUES ('Paris', 2100000), ('Lyon', 520000)
""")

spark.sql("""
    UPDATE lakehouse.bronze.villes
    SET population = 2133000
    WHERE nom = 'Paris'
""")

spark.table("lakehouse.bronze.villes").show()
\end{lstlisting}

\textbf{Cellule 3 -- Voir l'historique de la table}
\begin{lstlisting}[language=Python]
spark.sql("""
    SELECT committed_at, operation
    FROM lakehouse.bronze.villes.snapshots
""").show()
\end{lstlisting}

\begin{resultat}
La cellule 3 affiche \textbf{deux versions} de la table : l'insertion, puis la modification.
Un Lakehouse garde l'historique des données ; vous l'exploiterez dans le TP 1.
\end{resultat}

\section{Commandes utiles au quotidien}
% =====================================================================

\begin{center}
\renewcommand{\arraystretch}{1.25}
\begin{tabularx}{\textwidth}{@{}l >{\ttfamily}X@{}}
\toprule
\textbf{Je veux\dots} & \textbf{\normalfont Commande} \\
\midrule
Démarrer                           & docker compose up -d \\
Démarrer avec Trino et Superset    & docker compose -{}-profile full up -d \\
Voir l'état des services           & docker compose ps \\
Voir les erreurs d'un service      & docker compose logs -{}-tail 50 jupyter \\
Arrêter (en gardant mes données)   & docker compose -{}-profile full down \\
\bottomrule
\end{tabularx}
\end{center}

\begin{attention}
N'ajoutez \textbf{jamais} l'option \cmd{-v} à \cmd{docker compose down} : elle efface toutes les
données du Lakehouse. Vos notebooks, eux, restent dans le dossier \texttt{notebooks/}.
\end{attention}

\section{En cas de problème}
% =====================================================================

\begin{center}
\renewcommand{\arraystretch}{1.3}
\begin{tabularx}{\textwidth}{@{}>{\raggedright\arraybackslash}p{5.2cm}X@{}}
\toprule
\textbf{Symptôme} & \textbf{Solution} \\
\midrule
Docker Desktop ne démarre pas (Windows) &
  Activer la virtualisation dans le BIOS (Intel VT-x ou AMD-V), puis relancer \cmd{wsl -{}-install}. \\
\texttt{port is already allocated} ou \texttt{access permissions} &
  Le port est pris par un autre logiciel ou réservé par Windows : changez le numéro dans \cmd{.env}
  (ex. \cmd{PORT\_JUPYTER=8889}), puis relancez \cmd{docker compose up -d}. \\
Un service s'arrête tout seul, ou le notebook plante &
  Mémoire insuffisante : fermez les autres applications, restez sans le profil \cmd{full},
  ou baissez \cmd{JUPYTER\_MEM\_LIMIT} dans \cmd{.env}. \\
Erreur \texttt{RequestTimeTooSkewed} après une mise en veille &
  Redémarrez Docker Desktop (Windows : \cmd{wsl -{}-shutdown}). \\
\texttt{Permission denied} dans \texttt{notebooks/} (Linux) &
  \cmd{sudo chown -R 1000:1000 notebooks apps} \\
Téléchargement bloqué sur le réseau de l'école &
  Téléchargez chez vous, ou demandez la clé USB du kit hors ligne. \\
\bottomrule
\end{tabularx}
\end{center}

\begin{astuce}
Toujours bloqué ? Envoyez à l'enseignant la sortie de ces deux commandes :
\cmd{docker compose ps} et \cmd{docker compose logs -{}-tail 50 <service>}.
\end{astuce}
